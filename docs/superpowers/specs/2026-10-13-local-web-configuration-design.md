# subagent-delegation 本地网页配置设计

日期：2026-10-13。状态：**0.2.0 已按此规格实现；实际验收见 [实施记录](../../implementation-review.md)**。

本规格补充[开发计划](../plans/2026-10-13-npm-delegation-modes.md)。交付包括页面结构、静态视觉稿、终端对应关系、交互状态、服务边界和验收条件。网页必须真实调用本 npm 包的 CLI；网页、终端共用配置预检、锁、完整性校验、恢复基线和失败回退。CLI 字段与写入结果以开发计划第 7 节为唯一依据；重启提醒以第 6.4 节为唯一依据，本规格只定义呈现方式。

## 1. 决策与范围

用户要求所有业务功能可通过终端配置，也可从终端启动本地网页服务后配置。本轮 Q1–Q4 已由用户直接确认；其他常规设计选择按已核对的代决策授权采用最优推荐。范围仍为计划与设计，不扩展为代码实施、安装依赖、启动服务或 Git 写入授权。

| 决策 | 采用方案 | 依据 |
| --- | --- | --- |
| 选择后何时执行 | 编辑草稿，点击“应用”或“保存”后执行 CLI | 避免选择中途落盘、连续切换和误触；执行结果返回前不显示成功 |
| 配置范围 | 一个服务绑定一个启动时解析的 Codex home | 页面始终显示目标；切换 home 需在终端启动另一个实例，网页不能传入任意路径 |
| 前端技术 | 原生 HTML、CSS、JavaScript | 当前没有前端框架；设置表单不需要引入框架、构建工具或组件依赖 |
| 视觉 | 浅灰背景、白色表单、单一蓝色主操作 | 设置工具使用紧凑清晰的表单与列表，减少装饰和阅读负担 |
| 网页执行 | 固定 Node 可执行路径 + 当前包 CLI 入口 + 结构化参数 | 不搜索 npm/PATH 中另一份工具，不执行 shell，不维护第二套配置写入实现 |
| 四级保存 | `mode configure --definition-stdin` 一次提交完整 L1–L4 | 保留原单级命令；四级定义及活动部署共用一个计划、一个锁和普通失败回退 |
| 激活与编辑 | 切换档位与保存定义是明确的两种动作 | 保存非活动档位不激活；保存活动档位同步部署，按钮标为“保存并应用” |
| 终端与网页冲突 | 网页写操作必须携带读取时的 `configuration_revision` | CLI 在写入锁内检查；旧表单返回 `CONFIG_CHANGED`，零写入、保留草稿、提示重新比较 |

首版包含三种内置档位、自定义名称及四级配置、setup、查询、规则解释、非推理模型检查、显式推理验证、恢复预览及恢复。不增加聊天窗口、任务执行面板、任意命令终端、模式重命名/删除、远程访问、多用户账号或自动守护进程。

## 2. 页面结构与视觉

### 2.0 设计推敲与本轮取舍

**对象与任务：** 面向需要配置 AI 子代理的本机用户。主要任务是看清难度到模型的分配、调整定义、确认改动并写入指定智能体。原先“左导航 + 大表单 + 警告条”的布局可以套到许多设置页，草稿和已保存状态也不够醒目；本轮把四级配置与变更比较作为页面主体。

**设计决策树：** 已确认浅色/原生/单 home/点击执行 → 四入口用顶部导航 → L1–L4 配置与本次变更并排 → 根据当前/非当前/草稿状态决定按钮 → 目录建议、错误、未知与执行结果就地呈现。选择依据为此前已确认需求与常规代决策授权，无新增写命令、预算授权或服务范围。

**初稿比较：** 方案 A 保留左栏并为三档增加三张卡片；方案 B 采用顶部导航、单一四级矩阵、旁侧变更摘要。选择 B：四入口无需占用整条侧栏，三个档位无需营销卡片，右侧空间用于实际变化。界面只在被修改的等级使用浅蓝背景与“已修改”文字，其余部分保持安静。

```text
方案 A：左导航 + 多张档位卡片          方案 B：顶部导航 + 配置与变化并排
┌────┬───────────────────┐           ┌─────────────────────────┐
│导航│经济  适中  性能卡片│           │档位  规则  模型  恢复     │
│    │四级配置            │           ├────────────────┬────────┤
│    │统一保存            │           │档位与四级配置  │本次变化│
└────┴───────────────────┘           │修改字段        │操作按钮│
                                     └────────────────┴────────┘
```

**对照 brief 后修订：** 移除常驻侧栏、整页模型警告条和默认展开的终端区；将未知状态放到具体模型旁，将命令置于展开区，将主按钮与逐级变化放在一起。字体选本地系统中文与界面字体以贴近本机配置工具，等宽字体仅用于真实命令和可复制标识；不引入远程字体、统计仪表或装饰动效。所有文字左对齐，仅分段按钮居中。L1–L4 是实际难度等级，不画为流水线，避免让人误解四级需依次执行。

### 2.1 信息布局

顶部依次为工具名、Codex 与绑定 home、四入口导航；内容区最大 1280px。导航为“档位配置”“委派规则”“模型检查”“恢复配置”。顶层显示工具版本与已安装配置版本，二者不一致时给出明确升级入口。长 home 可展开完整路径，页面不允许编辑目标。未安装在档位页显示 setup，不虚构当前档位。

档位页标题下以“已配置：名称”显示磁盘记录，查看的定义另显示“正在编辑”或“正在查看”。不能使用“当前生效”“正在运行此模型”等未经宿主确认的文字；加载边界就近说明“使用新配置前请重启 Codex，运行生效未验证”。文件已写入、原生 Skill 已发现和运行已加载分别展示，不以重启替代发现路径/规则遮蔽检查。

桌面左侧约三分之二用于配置，右侧约三分之一用于本次变更及操作。经济、适中、性能、自定义采用同一原生 radio 组，保证互斥。选择自定义后再选择具体名称；没有自定义时显示“新建档位”与从哪个内置定义复制，不能擅自创建或激活。新建确认才执行 mode create，成功反馈“档位已创建，尚未设为当前”；取消后续字段修改不会删除它。

配置矩阵每级显示真实 L1–L4、易懂难度名称、任务示例、主模型、推理强度、备用与检查证据。内置定义为只读文本，提供“复制为自定义”；自定义提供原生 input/datalist 与 select 或可输入的 effort 建议。模型标识保持原值；可用中文标注“低（low）”“适中（medium）”“高（high）”，传给 CLI 的仍是原 effort 标识。未知标识照原样显示。

备用定义直接显示当前组合或“无备用”，展开后配置最多一个组合；高级解释及固定备用成立条件按需展开。模型检查信息就地显示，不用一条全页黄色横幅将所有未知状态表现为故障。常用字段始终可见，角色完整权限、文件变化和命令输入收进按需展开区。

右侧“本次变更”以同一读取版本比较旧值和草稿，逐级显示主模型、推理强度及备用的变化；变化数量按变化的任务等级计数，不按 JSON 属性或生成文件数计数。档位切换比较当前定义与目标定义；非当前自定义编辑比较该定义已保存值与草稿，并明确“保存后仍需设为当前”。无变化时显示“尚未修改”，禁用保存；初次 setup 则展示要新增的配置，保留显式 setup 按钮。

本地语义比较不调用 CLI、不改变配置、不证明文件预检成功。用户可点击“预览文件变更”执行同一写命令的 --dry-run；正式保存/应用仍重新预检、锁内检查原 revision。查看预览后继续编辑会使预览过时；“关闭预览”只关闭视图并保留草稿。正常保存不额外插入确认弹窗；恢复与推理验证沿用各自明确确认流程。

“查看终端命令”为可折叠区：提交前显示“将执行的命令”，结果返回后显示“本次执行结果”。只显示本次实际动作、脱敏 argv/stdin 和结果，页面输入未提交时不伪称命令已运行。完整四级 JSON 可独立复制；不拼接用户内容到 shell 管道。服务仍只保留最近一次安全结果，无持久化历史。

### 2.2 设计令牌

| 用途 | 值与规则 |
| --- | --- |
| 页面背景 / 内容表面 | `#F4F6FA` / `#FFFFFF` |
| 主文本 / 次文本 | `#253149` / `#526076`；次文本也需满足普通文字对比度 |
| 普通分隔线 / 控件边框 | `#D8E0EC` / `#7D899C`；交互边界不能只依赖浅灰分隔线 |
| 主操作 / 链接 / 焦点 | `#2457D6`；按钮白字；焦点 2px 实线，外偏移 2px |
| 错误 / 警告 / 成功 | `#B42318` / `#8A4B00` / `#166534`；总有文字和必要图标，不仅靠颜色 |
| 字体 | 本地界面优先系统 UI 字体，中文 PingFang SC / Microsoft YaHei；正文与标题同一 sans-serif，真实命令用 Menlo/Consolas；不下载字体 |
| 字号与行高 | 正文 16px/1.5，次级信息 14px/1.5，页标题 26px/1.3，字重 400/600 |
| 间距与圆角 | 间距 4/8/12/16/24/32px；控件圆角 6px，大配置区域 10px、展开区 6px；用层级和留白组织，不把每项功能包成卡片 |
| 控件 | 最低 44px 可操作高度；字段标签常驻，placeholder 不充当标签 |
| 动效 | 默认仅 120–160ms 的颜色反馈；支持 reduced-motion；无页面入场、发光或循环装饰动画 |

本轮使用 frontend-design 重整布局与文案，保留前轮 ui-ux-pro-max 的表单和焦点约束。核心六色为画布 #F4F6FA、表面 #FFFFFF、文本 #253149、次文本 #526076、操作蓝 #2457D6、控件边界 #7D899C；分隔与状态颜色为辅助语义。视觉重点是四级配置与本次变更，颜色不表示未核实的成本、速度、能力评分或模型权限。

不使用紫色渐变、机器人/星光图案、巨大欢迎语、宣传文案、玻璃拟态、悬浮装饰或密集状态卡片。页面文案使用“已配置”“设为当前档位”“可用性未确认”“配置已写入”等直接表述。

### 2.3 响应式与无障碍

1280–1440px：顶部导航，内容最大 1280px，左右留白至少 32px；配置与变化区约 2:1，间距 24px。1024–1279px：保持并排但减少非必要说明；768–1023px：变化区移到配置下方。375–767px：留白 16–20px，四入口可折行，每级用原生 details/summary 展开字段；折叠时仍显示模型、effort 与错误/修改状态。错误摘要跳转某级时先展开再聚焦。变更和操作跟随表单自然排版，不做遮挡软键盘/焦点的悬浮底栏。长路径、模型名、命令输出允许换行，页面不产生整体横向滚动。

导航使用正常链接和 `aria-current`；radio/select/input/button 使用原生元素及关联 label，所有按钮明确 type。表格使用 caption 与列标题；移动分组保留同样语义。备用展开使用按钮并维护 `aria-expanded`。执行中禁用重复提交，但提供文本进度；成功采用 `role=status`，失败提供可聚焦错误摘要及关联字段说明，保留用户输入。弹窗遵循焦点进入、约束、Escape、关闭后还原；优先原生 dialog，失败时必须验收浏览器实际行为。普通文字对比度至少 4.5:1，交互边界和焦点至少 3:1；真实界面还需键盘与屏幕阅读器检查。

### 2.4 其他三页的使用体验

**委派规则：** 首屏为当前配置与四职责摘要，完整规则按主题展开；难度与职责是两项独立选择，用户点击“查看解释”后执行 explain。结果优先显示主模型/effort、实际需使用的角色、原职责与备用条件，后面再展开原因码和来源。复杂扫描仍保留只读契约，不能由矩阵中的模型推断权限。外部覆盖和未检查范围放在“配置来源”区域，遇 unknown 说明缺哪份证据，不展示完整私有指令。展开、收起和筛选已取得的结果不再启动 CLI。

**模型检查：** 主按钮固定为“检查账号与目录”，旁边展示检查对象和上次时间；实际推理验证是独立动作。目录支持与该次调用结果使用不同列，未知显示原因和下一步；不把所有 unknown 当黄色故障。选择单组合验证时先列出模型与 effort，批量时列出本次去重组合及上限，确认额度/费用后才生成 --verify。检查期间给真实的等待说明，不显示伪造百分比或逐项成功动画。目录检查的 passed 只表示检查完成，不代表账号调用权限已验证。上下文或配置版本改变后标记旧结果，并保留原检查对象；返回档位页可引用目录建议，原草稿不因检查结果被覆盖。

**恢复配置：** 默认先查看恢复能力和绑定 home，主动点击“预览恢复”后执行 dry-run。结果按“将清除”“将恢复/保留”呈现本库角色/规则、全部自定义名称和安全路径；缺基线/冲突先给阻断原因。最终按钮明确“恢复原配置”，沿用一次确认，不添加重复键入路径等额外步骤。成功后显示“原配置已恢复，请重启 Codex 后使用原委派规则”，刷新未安装状态及列表，不保留旧当前档位；普通失败分别显示未写入、已回退或仍有残留，保留具体修复入口。

窄屏在展开的“将执行的终端命令”内提供“预览文件变更”，保留与桌面相同的 dry-run 入口。确认弹窗、错误摘要和返回编辑器动作维持原草稿与焦点；任何读写动作都使用既有白名单命令，不为美化增加新写命令。

## 3. 全功能网页到 CLI 的对应

下面是拟开发协议。每个业务读取/执行动作实际启动当前包 CLI 子进程；展开说明、导航、输入草稿和选择按钮属于页面呈现，不产生配置写入。

所有 home 业务请求固定附加启动时的 `--agent=codex`、`--codex-home=<绑定目录>` 与 `--json`。写动作附加读取时的 `--expect-revision=<版本>`。表中省略这些公共参数；模式选择统一解析内部 id，名称作为数据。创建名称等位置参数支持 `--` 后传入；模型等值采用单个 `--model=<值>` 参数，避免以 `-` 开头的值被误解析为选项。

| 网页入口/动作 | 对应 CLI | 提交/状态含义 |
| --- | --- | --- |
| 初始状态、刷新、规则详情 | `status --details` | 只读；显示检查范围、外部覆盖与未验证结论 |
| 档位选择列表 | `mode list` | 内置与绑定 home 的自定义；未安装仍可展示内置预览 |
| 查看选中档位 | `mode show MODE` | 预览不激活，显示定义来源与当前记录选择 |
| 首次配置 / 显式升级 | `setup [--mode MODE]` | setup 才写入；升级默认保留选择，确认预览后执行 |
| 应用另一档位 | `mode set MODE` | 点击后执行；成功再更新当前档位 |
| 新建档位 | `mode create NAME --from MODE` | 复制四级、生成 id、不激活；成功进入该定义 |
| 保存自定义全部四级 | `mode configure MODE --definition-stdin` | 严格 JSON 经 stdin；一次保存全部；活动定义与部署同一事务 |
| 单级命令对等性 | `mode configure MODE --level ... --model ... --effort ...` | 终端保留单级入口，网页使用整表入口，语义与验证复用 |
| 规则页等级/职责解释 | `explain --level Lx --role ROLE [--mode MODE]` | 明确等级、预设与备用条件；不进行任务分类或创建子代理 |
| 模型页检查目录 | `models check` | 非推理；目录列出与账号成功调用分别显示 |
| 模型页验证实际调用 | `models check --verify [--model MODEL --effort EFFORT]` | 显式确认费用/额度后点击；沿用最多四组合、15/60 秒边界 |
| 配置预览 | 相同写命令加 `--dry-run` | 零配置写入，展示完整变更计划；不替代实际执行时再预检 |
| 恢复预览 / 恢复原配置 | `restore --dry-run` / `restore` | 显示目标与全部自定义清理；成功后重新查询为未安装 |
| 帮助与版本 | `--help --json` / `--version --json` | 不带 home/agent；CLI 返回统一 envelope 的 data.help / data.cli_version，默认终端文本输出保留 |

写命令 `--json` 使用统一 `{report_schema_version:1,data,errors}`。`data` 至少含 action、agent、目标安全路径、`result=preview|applied|unchanged`、配置阶段状态、changed_files、revision_before/after、mode、warnings、post_check、restart 和 runtime_verification。`post_check` 为包含 status=not_requested|passed|incomplete|failed、source_revision、mode、checked_pairs、configuration_changed 和诊断的对象；配置已成功但检查失败时主文案为“配置已写入，模型检查未完成”，不引导用户重复写入。失败的 result 可为 failed/unknown，configuration_status 区分 not_written/written/unchanged/rolled_back/partial/unknown。零变化 before/after 相同，dry-run 的 revision_after 为 null。后检查使用本次提交的模式与组合，固定 revision_after；后来终端改变模式时标注检查对象已过时、要求刷新，不偷换为新配置结果。实际账号/供应商上下文变化或无法确认则保留 unknown，最终只返回一次 CLI JSON。restart 复用主计划第 6.4/7.5 节的 required/reason/message；网页不得根据模型目录成功自行推断已经加载。result/configuration_status/restart 的组合完全遵守主计划第 7.5 节唯一结果表，包括预检拒绝的 not_applied，不另定义成功条件。

完整定义 stdin 示例，未知字段、缺级、无效类型或超过 64KiB 拒绝。L1–L4 都显式带 fallback；null 为清空，没有遗漏时继承旧备用的歧义。整表模式与单级参数互斥，不能改内置或改名称。

```json
{
  "levels": {
    "L1": {"model":"gpt-6-luna","effort":"high","fallback":null},
    "L2": {"model":"gpt-6.1-sol","effort":"medium","fallback":null},
    "L3": {"model":"gpt-6.1-sol","effort":"high","fallback":null},
    "L4": {"model":"gpt-6-astra","effort":"low","fallback":{"model":"gpt-6.1-sol","effort":"high"}}
  }
}
```

## 4. 操作流程与边界状态

| 场景 | 页面行为 | 配置/命令保障 |
| --- | --- | --- |
| 选择不同档位 | 标注“待应用”，主按钮显示“设为当前档位”；已配置标识保留 | 只执行预览读取；应用点击才调用 mode set |
| 修改自定义字段 | 显示逐级变更、修改标记和“取消修改”；离开时提示保存/放弃/继续编辑 | 不能边输入边写入；草稿不混用已保存定义，保存一次提交全部 |
| 取消修改/选择 | 清除本地草稿回到该定义的保存快照；有外部变化先清草稿再重读；取消选择回到已配置档位 | 零配置写入，不切换、不删除已 create 的新档位；执行中禁用取消写入，预览关闭保留草稿 |
| 保存非活动自定义 | 按钮“保存档位”，提示“已保存，尚未设为当前”；有草稿时禁用“设为当前档位”，提示先保存或取消 | 不隐式激活；保存完成后独立 mode set，不能应用磁盘旧定义却展示未保存草稿 |
| 保存活动自定义 | 按钮“保存并应用”，显示将更新新委派的预设 | 一次 configure 事务更新定义与部署；现有子代理不热切换 |
| 终端已改配置 | “配置已被其他操作更新”；保留草稿，提供“刷新后比较” | 锁内 expected_revision 不匹配 → CONFIG_CHANGED，零写入，无自动重试 |
| 配置文件被手改/损坏 | 显示原因、安全路径和建议；禁用受影响写动作 | 完整性/归属检查仍阻止覆盖，网页没有强制开关 |
| 初次未安装 | setup 表单及内置定义预览；恢复显示无需恢复 | 不虚构当前适中，不自动 setup，不运行模型验证 |
| 旧版缺恢复基线 | 恢复不可用，显示需要原备份或人工处理的具体原因 | RESTORE_BASELINE_UNAVAILABLE；不猜测删除历史规则 |
| 模型目录未知 | 保留配置值，文字“可用性未确认”及原因，允许显式检查 | 不是不可用；不偷偷替换模型 |
| Astra 明确拒绝 | 显示主配置、一次备用候选及成立条件，帮助定位 | 沿用主代理 Skill 执行的备用规则；页面不承诺已自动派发 Sol |
| 检查某组合后档位变化 | 结果注明检查的档位/版本及时间 | 显示开始 configuration_revision、组合 source_revision 和 configuration_changed；过时或无法确认的结果不当作当前配置权限证据，不永久保存账号结论 |
| 请求中断 / 响应格式错误 | 提示“结果暂无法确认”，保留草稿并提供刷新 | 不自动重发写命令；可能已提交，先读状态核对 |
| 双击/多标签同时提交 | 本页提交中禁用；服务拒绝重复或繁忙动作 | 写操作仍以 CLI 锁和版本校验为准，不能只靠按钮禁用 |
| 恢复成功 | 清空页面旧模式和自定义缓存，刷新 status/list；回到“未安装” | 网页资源在 npm 包，不在 Codex home；restore 不删除服务资源 |
| 服务停止 | 禁用提交，提示终端重新 serve 与刷新 | 页面关闭不停止服务；Ctrl+C 等正在写入安全结束后停止 |

加载/空数据/失败/成功/禁用均有文字状态。页面获得焦点或用户点击刷新时重新查询，操作结束也刷新；无草稿时更新显示，有草稿时只提示外部变更，不覆盖草稿。不加入定时后台监控或 WebSocket。遇 BUSY 保留上次结果并明确其时间，用户可重试只读查询。

恢复页面单独显示：绑定 home、将移除的本库规则与四角色、全部自定义数量和名称、原有配置及无关文件保留、请重启 Codex 后使用原委派规则。先执行 dry-run，用户点击确认恢复再执行 restore；预览版本变化则要求重新预览。确认只针对该次恢复，不授权模型调用。

成功应用另一档位、setup 或保存当前自定义后，结果区持续显示“配置已写入，请重启 Codex 后使用新委派规则”，采用 role=status 宣读。提醒在结果旁保留，不仅用会消失的 toast；不提供网页自动重启、不记录“已重启”开关。恢复成功同样提醒重启后使用原规则。非当前保存只显示尚未应用，预览显示正式应用后需重启；零变化可以提醒此前尚未重启的用户。结果未知时先刷新核对，不先提示已切换。具体 required 值与文案由 CLI 决定。

网页刷新不能证明智能体已经加载，模型检查也不能消除提醒；status 保留使用前重启及运行未验证的说明。重启须由用户在安全处理运行任务后执行，不通过关闭网页、重启本地配置服务或另开对话冒充重启 Codex。

### 4.1 模型选择与字段反馈

复用最近一次 models check 返回的同 home/供应商上下文模型目录，页面会话内给出输入建议与原 effort 支持值，注明检查时间及范围。目录列出、参数支持、请求成功、实际身份是分开的信息，不用一个绿色“可用”合并。目录缺项、未完整分页、隐藏项缺失、客户端/供应商上下文未知时继续允许原值和手填；不能自动移除、替换模型或选定 effort。

更换模型后保留用户原 effort，并重新显示支持信息；结构错误（缺必填项、备用只填一半、非法字段）阻止提交，定位到具体等级。可靠当前检查明确不支持某 effort 时给出具体提示及支持值，实际写入由同一 CLI 预检裁定；客户端缓存不能新增与终端不一致的拦截。目录与权限诊断不证明一定可调用，符合静态定义的预设可保存，运行失败/备用仍按原委派规则处理。

只有焦点位于明确主按钮时 Enter/Space 执行该动作；字段中的 Enter 用于编辑或选择候选，不触发配置写入，原生 form 的隐式提交需阻止；有草稿的离开提醒只覆盖本页导航、档位切换和服务页面关闭的浏览器能力。刷新/重启后草稿可能丢失，首版不保存模型草稿到 localStorage 或磁盘；执行结果未知时先读状态，不能用浏览器恢复草稿自动重发。

### 4.2 操作命名与按钮状态

| 页面状态 | 主动作 | 次动作 | 用户预期 |
| --- | --- | --- | --- |
| 已配置当前定义、无修改 | 无修改（禁用） | 复制为自定义/检查模型 | 不制造重复写入 |
| 已配置当前自定义、有草稿 | 保存并应用 | 取消修改/预览文件变更 | 一次 configure 保存四级并更新当前配置 |
| 非当前自定义、有草稿 | 保存档位 | 取消修改/预览文件变更 | 保存后仍需单独设为当前；不提供含糊的保存并激活 |
| 非当前已保存定义或内置定义 | 设为当前档位 | 取消选择/预览文件变更 | mode set 使用页面展示的已保存定义 |
| 未安装 | 配置 Codex | 预览文件变更 | 显式 setup；不是 mode set |
| 正在执行 | 保存中/切换中/恢复中 | 展开本次命令 | 防重复提交；不允许取消按钮误导为可撤回已提交写入 |

完成文案与动作保持一致；“取消修改”“关闭预览”“取消选择”明确不同，不使用笼统“取消”混合撤回写入与丢弃本地输入。

模型页默认“检查账号与目录”；“验证实际调用”说明可能消耗额度/费用、当前去重的组合或单个选择。用户主动确认后才生成 --verify，请求过程中关闭/重连页面不能自动再次验证。结果区分目录支持、该次请求成功和实际身份未验证，不显示邮箱、凭据或原始 RPC。

## 5. 本地服务与执行协议

### 5.1 终端启动

```sh
# 拟开发：随机空闲端口，终端打印实际本地 URL；--open 显式打开系统浏览器
subagent-delegation serve --agent codex --open
subagent-delegation serve --agent codex --codex-home "/path/to/codex-home" --port 4318
npm exec --package="/path/to/subagent-delegation-0.2.0.tgz" -- subagent-delegation serve --agent codex --open
```

serve 前台运行；默认 --port 0 让系统分配空闲端口，支持 0 或 1024–65535 的显式端口，占用则报错不自动换另一个指定端口。只监听 `127.0.0.1`，打印 `http://127.0.0.1:<实际端口>/`。--open 失败时保留服务并显示可手动打开的 URL。不支持 --host、0.0.0.0、局域网、远程映射或自启动；退出不撤销配置。未安装也允许 serve，读取失败显示诊断，启动本身不写配置、不检查账号、不推理。

### 5.2 唯一命令执行路径

```text
页面动作与结构化数据
    → 本地服务：校验来源、会话、动作、字段、请求大小
    → 动作白名单生成固定 argv 和 stdin
    → spawn(process.execPath, [当前包内 CLI 绝对路径, ...argv], {shell:false})
    → CLI：解析、版本/归属预检、锁内 revision 校验、统一 applyPlan
    → CLI JSON + exit code
    → 页面呈现结果，再读取最新状态
```

服务拒绝任意 command、shell、工作目录、home、project、可执行路径、环境变量、developer_instructions 和未知字段。规则页项目覆盖检查仅使用服务启动时的 cwd；首版网页不添加任意项目路径输入。服务不得直接调用 applyPlan 或写目标文件。参数使用 argv 数组，中文、空格、引号、反引号、`$()` 只作为数据；实际安全处理依据 [Node 子进程 API](https://nodejs.org/api/child_process.html)，不拼接 shell 文本。

业务 API 使用单一 `POST /api/actions`、action 白名单和严格类型；只读业务动作也从该入口调用 CLI。静态资源限定明确路径，不能把目录挂成任意文件服务器。`GET /api/bootstrap` 只返回绑定 home、版本、会话 nonce 等服务元数据；不绕过 CLI 返回配置。API 结果附 action、脱敏 argv、exit_code 和 CLI envelope。服务进程异常、超限、未知报告版本或无效 JSON 报 COMMAND_RESULT_INVALID；不把原始 stdout/stderr 作为网页输出。

单实例最多一个业务子进程，繁忙返回 BUSY；不无界排队；CLI 的跨进程锁仍是最终边界。页面首次读取 status/list/show 按序，不并发堆叠；所有 home 报告的 data.configuration_revision 一致才发布给表单。不同则丢弃整组并最多重读一次，仍变化报告 BUSY，保留旧报告时间和草稿。restore 使旧自定义 id 消失时先重取 status/list，再决定 show；不无限重查已删除定义。静态页面与 bootstrap 不受业务查询阻塞。模型检查/验证沿用明确期限；写子进程等待安全完成，不因 HTTP 连接断开强杀。CLI 对 SIGINT/SIGTERM 在写入/回退临界期延迟处理，安全结束再退出；Ctrl+C 停止接收新动作，等待已在提交的写命令结束或按 CLI 已实现的取消/回退流程退出，不承诺断电恢复。不会后台重新提交未完成请求。

服务只保留最近一次脱敏结果，不保存任务/命令历史数据库，不输出账号令牌、cookie、nonce 或原始私有配置。界面中的对应命令说明与结构化 argv 来自实际执行映射，不能只打印一条命令却在另一套路径写文件。

### 5.3 浏览器边界

仅绑定 loopback 不足以作为写接口保护。每次请求校验精确 Host；业务 POST 必须来自实际服务 URL 的 Origin，拒绝缺失、null 和其他来源，无跨域许可。短期服务会话存内存，实例独立的 HttpOnly、SameSite=Strict cookie，根页面响应设置实例会话 cookie；页面同源 bootstrap 取得与会话绑定的随机 nonce 后用专用 header 提交；nonce 不出现在 URL、终端和日志。bootstrap 同源读取，并校验浏览器 fetch 来源。HTTP 请求只接受 JSON、最高 128KiB（UTF-8 字节，包含 action 包装）；规范化传给 --definition-stdin 的正文仍最高 64KiB。两个边界分开测量，避免相同有效定义只在网页被包装大小拒绝；超限在启动 CLI 前拒绝。

SameSite 只作为补充，来源校验和 nonce 按 [OWASP CSRF 指引](https://cheatsheetseries.owasp.org/cheatsheets/Cross-Site_Request_Forgery_Prevention_Cheat_Sheet.html)共同验收。固定 Host 拒绝 DNS 重绑定域名；不因 localhost 名称存在而放宽任意来源。设置 CSP 仅允许本包同源资源、禁止 framing/base/object，采用外部本地 JS/CSS，无 CDN 与内联脚本；页面输出文本通过安全文本节点构造。CSP 实施依据 [MDN CSP 文档](https://developer.mozilla.org/en-US/docs/Web/HTTP/Guides/CSP)。这些是首版浏览器写入边界，不是多用户/恶意本机进程隔离保证。

### 5.4 CLI 配置版本与查询一致性

版本生成、instance_id 生命周期、完整观察快照、状态权限字段、零变化/dry-run 与 --expect-revision 行为，统一遵守开发计划第 7.1/7.5 和第 8.1 节。服务不能实现另一个 revision 算法。home 覆盖入口与角色清单参与版本；项目查询只检查启动 cwd 的候选，不改变 home 写入版本。

status/list/show 仍按第 5.2 节串行取得相同 data.configuration_revision 后才发布表单。无可信版本、已知规则被遮蔽或配置版本需要升级时，页面显示 CLI 诊断和对应操作，不提供强制写入；restore 不被不相关的发现故障阻断。CLI/网页遇冲突都保留草稿、要求重新比较，不自动刷新版本并重放。

## 6. 实施与验收

先实现 CLI 的整表提交、写结果 JSON 和版本契约，再实现 Node 标准库本地服务，最后实现原生页面。UI 不先造一套假写入接口。正式开发前使用 frontend-safe-development；当前 SVG 仅为视觉稿，不含脚本、API 或可运行表单。

- [ ] 一次四级提交第三步故障后安全回退；校验失败零配置写入，不能仅证明四次单级命令都成功。
- [ ] 串行状态/list/show 间注入外部切换与 restore，整组有限重读后不会混合版本；解锁后后检查仍绑定原提交。
- [ ] 两个标签与终端切换后，旧表单 CONFIG_CHANGED 且保留草稿；dry-run 后终端再次改变也拒绝旧预览执行。
- [ ] 用临时 home 对每个业务动作验证确实启动打包 CLI，argv/stdin 与等价终端操作一致；结果、退出码与文件快照一致。
- [ ] `--definition-stdin` 严格拒绝缺级、未知权限字段、超限输入及与单级参数混用；中文/引号/命令替换等不能触发 shell。
- [ ] HTTP 检查跨站 Origin、null/missing Origin、恶意 Host、错误会话/nonce、JSON 超限、路径遍历、任意命令字段、输出脱敏和并发 BUSY。
- [ ] 未安装、旧版、漂移、规则被遮蔽/未发现、模型未知、认证/额度失败、验证不支持、后检查失败、响应丢失、服务重启均有明确状态，不自动写入或付费调用。
- [ ] restore 后服务仍可查询，页面移除旧模式和自定义；旧草稿拒绝提交，重新 setup 必须主动执行；模型检查结果不能沿用为新配置权限。
- [ ] 完整结果表中的成功/定义保存/零变化/预检拒绝/完整回退/部分回退/未知状态正确呈现；模型检查显示开始/来源版本与变化，passed 不冒充调用权限 verified。
- [ ] 应用/活动保存/setup/restore 持续显示重启提醒并宣读；未知、完整回退、零变化、非当前保存和预览的文案遵守 CLI；检查成功不能显示运行生效。
