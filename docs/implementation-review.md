## 当前约定

- 内置档位的命令、配置 id、状态记录、生成 JSON、查询和网页统一为 `cut / official / high / fire`，不保留名称映射。
- Skill 名称、目录和调用方式统一为 `agent-fit` / `skills/agent-fit` / `$agent-fit`；CLI 为 `agent-fit`。
- 仅支持当前状态格式和版本，只管理 agent-fit 安装。
- 不支持的状态格式、路径或档位引用返回 `STATE_INVALID`；版本不一致返回 `VERSION_MISMATCH`。校验在写入前完成，不转换或覆盖已有配置。
- 当前版本的同版本重复配置、档位切换、自定义和首次恢复基线保持有效。

## 使用边界

Skill 由 AGENTS 入口及角色指令要求读取，没有宿主委派拦截器。模型目录列出不证明账号请求权限；实际验证使用独立 Responses 请求，无工具和项目材料；请求成功与供应商报告的身份分别核验。缺少身份元数据仍不通过，不验证供应商内部上游路由。此前 0.6.0 验收时，真实供应商对 Astra/ultra 返回 HTTP 400 / model_not_found，失败记录已保存。当时从该供应商 /models 读取到 13 个候选，其中无 Astra；目录来源及结果已按 home 保存，未自动执行真实批量推理。第三方候选通过自己的 /responses 验证，默认参数可调用与指定强度严格验证分别呈现，目录变化后停止批量调用。

未验证其他操作系统、全部 Node 22.x、真实桌面会话加载、读屏器、真实 ChatGPT OAuth 推理或系统凭据库授权验证。多文件操作不保证断电/崩溃时整体原子；残留锁需人工核对。并发保护不提供对恶意本机进程的内核级比较交换。
