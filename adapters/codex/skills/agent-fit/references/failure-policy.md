# Failure policy

请求故障根据宿主可信的结构化 code、type 和请求阶段分类。HTTP 状态或自然语言报错不足以确定原因；无法分类时保留 unknown，不自动升级或替换。请求成功而结果未达验收，按下面的质量升级处理，不能标为模型不可用。

| 情况 | 处理 |
| --- | --- |
| 认证失效、账号或工作区权限不足 | 停止该路径，提示用户处理账号；不读凭据、不更换供应商，不把目录存在当作权限 |
| 额度、账单或预算限制 | 停止新增请求，不触发备用；不能把更便宜模型当作绕过额度的方法 |
| 临时限流、服务故障 | 在原预算内按宿主 Retry-After 有限重试，不提前重试；当前档位允许备用且重试后仍失败时，在剩余次数与等待预算内自动尝试本级唯一备用；累计重试等待将超过 30 秒则停止 |
| 模型或 effort 不支持、输入/工具/上下文能力不符 | 使用明确且满足原能力与验收的备用；没有候选或授权则 BLOCKED，不静默删减输入或验收 |
| 资料缺失、工具故障、目标冲突、验收不明确 | 先补前提，仅阻断受影响部分；换强模型不解决这些原因 |
| 结果未达原验收且证据充分 | 按质量升级核对原因和候选组合，限定困难部分；不使用可用性备用掩盖质量问题 |
| 超时、取消、停止状态未知 | 区分请求前失败与已启动工作。写入职责先确认旧 worker 停止并核对部分产出；未知时不得创建第二个同范围写入者 |

备用必须同时满足本任务 task_profile 快照中的 fallback_conditions：用户选择、原预算、宿主模型与 effort 支持、原任务输入及工具能力、原职责与验收、原写入 worker 已停止。条件码是待核对前提，不授予新的委派权限。cut、official、high 以及用户已选择的自定义档位，默认允许原已授权任务自动使用本级非空 fallback，包括按值复制的备用，无需逐次确认；仅创建、保存或预览候选不构成选择，用户明确锁定模型或禁止降级时不切换。自定义本级 fallback 为 null 时阻断该接续，不借用其他档位或 fire 的父代理继承规则。备用耗尽后停止该委派并报告原因、实际组合与部分产出，不尝试其他模型或切换档位。备用使用 task_delegate 显式指定 model/effort，保留原职责；L3、L4 不自动降到 Luna。

## 质量升级

1. **证明未达验收**：主代理核对原测试、证据或明确验收条件，指出具体错误；子代理自报完成、表述不合偏好或未分类故障都不足以升级。资料、工具、环境、凭据或目标冲突先补前提，不能靠换强模型解决。
2. **确定下一次为何有用**：方法或交接遗漏可在补正后有限重试原组合；证据显示推理深度不足或新暴露复杂约束时，重评困难部分等级与保障要求。原任务已授权，且用户选择、原预算和宿主能力允许时，由主代理在原任务快照中选择有针对性的同级任务候选或更高等级主组合；职责、允许动作与验收保持不变。显式指定模型/effort，固定角色不匹配时使用 task_delegate；不使用本级 fallback 作为质量升级，不自动切换档位或换供应商。
3. **比较实际组合**：先比较快照中的任务候选，再核对后续等级。Astra/low 结果有推理不足证据时，可在同级 L3/L4 选择已配置 reasoning 的 Astra/medium，计为质量升级；普通自动路由到 medium 后不再提高 Astra 强度。high/fire 的明确选档授权及已选择自定义的显式组合保持有效，详见 [任务候选](task-routing.md)。相邻等级组合相同时不重派，继续核对下一不同组合；到 L4 仍无合适的不同组合时，报告已达当前档位上限。high 的 L3→L4、fire 的任意等级变化都不增加模型或 effort；如有新证据或具体方法修正，可在剩余额度内重试原组合，并如实称为重试。自定义更高等级或不同候选不保证更强，须核对能力证据；不机械执行“先加 effort”或“先换模型”。
4. **限定接续范围**：先确认旧写入者已停止并检查部分产出，只交接仍困难的部分及必要上下文，保留完整验收。升级后的结果仍由主代理核验；未通过时按剩余额度处理，次数耗尽或无合适候选时停止该委派，返回 PARTIAL/BLOCKED 与未完成部分，继续独立工作。

每任务最多三次主代理发起的委派，初次、重试、质量升级与备用共用计数；拆分困难部分不重置计数，同一组合最多额外一次。累计重试等待不超过 30 秒并遵守 Retry-After；宿主已重试或次数未知时不叠加重试。不自动撤销他人修改，异常/部分结果仅作 PARTIAL 证据返回。

经济模式的复杂任务不能自动降到 Luna；fire 检查失败、未完成或最高组合不可用时，按下文 [fire 验证与继承备用](#fire-验证与继承备用) 执行。

## fire 验证与继承备用

仅内置 fire 启用此门槛。每个会话首次使用前，对目标 model/effort 实际调用验证，要求请求成功、可信运行 metadata 的模型与强度匹配、检查上下文与当前会话一致。目录列出、参数支持、用户口头确认或子代理自报不能代替验证。可使用 `agent-fit models check --verify --model gpt-6-astra --effort ultra`；若宿主无法隔离全部工具、委派及外部副作用，不发送验证请求，按检查未完成处理。

同一会话可复用有效验证结果；model、effort、供应商或账号变化后重新验证，不保存跨会话验证缓存。重新委派时仍核对结果适用性；失败或未知结果不能复用为成功。

检查失败、未完成或最高组合不可用时，明确说明原因，使用用户明确指定的模型与推理强度；未另行指定时，继承父代理当前实际使用的组合，不切换到 high。使用未固定的 task_delegate，保留原职责、范围和验收。核对全局子代理默认与角色覆盖；需要显式参数才能保证父代理组合时显式传入。无法确认父代理实际组合时仅阻断该委派，不猜测模型或 effort。备用仍须满足原预算、工具能力和写入者已停止等条件；不能绕过认证、额度或权限限制。
