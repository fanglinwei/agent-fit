# 离线校准

仅在用户要求评估或调优时使用。日常委派沿用 Skill 的定性信号与当前档位，不增加分类模型、训练服务或持续采集。评估不写当前模式，不修改账号、供应商或用户默认组合。

## 分清评估目标

| 目标 | 让候选完成什么 | 能证明什么 |
| --- | --- | --- |
| 配置链路预检 | 主代理直接执行配置查询并核对解析与职责契约，无需模型候选 | 配置读取流程正确；不能证明等级判断或模型能力 |
| 分级规则核验 | 根据相同任务事实给出等级、前提与理由，主代理另行查表 | 规则理解与判断是否一致；不能证明所选模型能完成任务 |
| 接续规则核验 | 根据失败证据、已用次数及配置判断下一步动作、组合与停止理由 | 决策是否遵守规则；不能证明宿主已执行重派 |
| 组合能力评估 | 实际完成相同任务，按原验收核对产出 | 这些任务上的结果；不能从少量样本推出通用能力排名 |

任务信号分别起作用：歧义与耦合影响推理需求；范围限定职责和上下文；可验证性与错误后果影响保障要求；时延只在合格候选间取舍。不将它们相加为未经校准的数字总分。高影响且难验收时至少 L3 是本地保守下限，不是来源项目或本次试验已证明的结论。

## 先预检配置链路

比较模型候选前，由主代理用现有工具核对本次涉及的查询与 [JSON 契约](configuration.md#配置查询与失败分流)，记录实际使用的配置来源与版本或摘要。涉及非活动预览或自定义档位时分别核对，不能从活动模式推断；即使返回了 `data`，退出非零或有错误也不算成功。只读查询不需要模型验证请求，也不为此额外派发子代理。

预检未通过时先修复受影响的本地配置、接口或材料，继续其他独立工作，不把查询故障记为模型能力失败。预检通过后再冻结下面的候选评估；静态预检不能代替实际任务验收或可信运行身份。

## 分级边界核验

分级核验分别记录任务本身复杂度、保障后拟采用等级、是否需先补前提及理由；拟采用等级明确不等于已可派发。输入案例与预期判断分开保存，预期中写明本地规则依据及允许的判断范围，开始后不为匹配答案修改验收。被测上下文只判断等级、前提和理由，主代理再用现有 CLI 取完整组合与角色契约。

分别核对等级和实际组合：相邻等级可能共用组合，分级一致也不证明该组合能完成任务。案例应覆盖文件数、职责名称、时限等干扰，以及材料缺失与任务内在不确定性的区别；报告规则一致性，不能把同一批案例算成多次独立重复，也不能只因两版规则返回相同答案就认定能力等价。未发现违反原规则的证据时保留原分级与默认映射，不为扩大文档而追加规则。

同级候选核验分别冻结最终等级和 task，覆盖机械/有界/扫描/深度/复杂/不确定/推理候选、保障下限阻止低等级路由、未配置 latency 的停止、高强度档位已选择与仅预览的区别。核对完整候选及其备用进入任务快照，低到 medium 的同级质量升级不重置计数。配置测试只证明选择与保存一致，不证明图示组合的能力或性能；真实任务校准仍按下文独立样本执行。

## 接续规则核验

冻结失败类别及证据、已用委派次数、同组合重试次数、等待预算、旧写入者停止状态、用户限制与完整配置。评估上下文只返回下一步动作、完整组合、派发角色、接续后的计数和理由，不实际发请求或执行案例任务；预期答案单独保存。核对质量失败与可用性故障、相同组合的名义升级、拆分后计数、停止状态未知及认证/额度/原因未知时的停止，以及自定义备用存在、为空或被用户禁止的分支。验收比较动作与不变量，不能用规则文字存在或候选自报通过替代；一次批量案例仍只是一批决策样本。

## 冻结任务与候选

1. **任务**：优先从实际使用中选择容易混淆的等级边界，记录材料版本或摘要、输入、允许工具、职责与原验收。若评估 Skill 行为，实际提供待测 Skill 并记录版本；只给代码片段的推导题不能证明 Skill 生效。测试集需覆盖目标使用场景；临时构造题和同仓库小样本只作试跑。分级核验的预期等级、能力评估的正确答案与其他候选产出均不交给被测候选。
2. **候选**：从内置或自定义档位快照读取完整 model + effort，按实际组合去重；可比较非活动档位而不切换当前模式。优先检验有实际区别且存在争议的两种组合，不遍历所有模式与等级。跨模型比较整个组合；只有其他条件固定时才把差异归因于某个因素。
3. **验收**：开始前确定完成条件、重要错误的判定与核验方法，保留预期结果或验证命令。主代理或原要求的独立验证者判定，不用被测代理自报完成代替验收。用于调整规则的样本与最终复核样本分开。
4. **预算与隔离**：开始前明确候选数量、重复次数、时间/资源预算及停止条件。各候选使用相同提示与材料，在独立上下文和运行范围完成；不共享答案或改写原验收。写入任务使用各自的授权目录，禁止同时修改共享工作树。交错执行顺序或记录时段差异，避免将缓存、排队或并发影响误判为模型差异。

可从两个有差异的候选、少量代表任务开始做流程试跑；单次结果不足以调整默认映射。若重试或补做，保留首轮失败并单独记录；不能重新编号掩盖返工，原 Skill 的委派次数、写入者停止与故障处理限制继续适用。任务前提不具备、请求未启动、工具失败与答案错误分别保留。

配置取值优先使用现有 `explain` 查询，从 JSON 的 `data` 对象读取结果，每条保留 mode_id、level、requested_role，主代理按冻结配置核对完整组合与职责契约。禁止工具的手工推导题应单独标记，不能代替实际查询流程的验收；答错后开放工具属于变更条件的复测，需单独记录，不能据此宣称原条件下通过或模型能力提高。

## 记录与判定

仅在本次获授权评估的输出位置记录必要证据，剔除敏感材料；材料版本可用摘要或受控位置引用。每次尝试至少保留下列适用项，无法取得的值填 unknown/null，并说明原因：

| 项目 | 记录内容 |
| --- | --- |
| 任务与尝试 | 任务 id、输入版本/摘要、职责、验收版本、尝试序号与上下文隔离方式 |
| 请求组合 | 候选来源与请求的 model、effort；这不证明运行生效 |
| 实际组合 | 宿主可信运行 metadata 中的模型/effort、证据来源，以及 matched/mismatched/unverified；子代理自报无效 |
| 执行状态 | completed/failed/incomplete/not_started/unknown，及已核实的失败类别 |
| 产出与验收 | 实际答案或产出位置、判定者、pass/fail/unjudged、失败位置与复核依据 |
| 耗时与资源 | 同一测量口径的端到端耗时，含启动、交接、核验及返工；可信 token/账单来源，没有证据不估算费用 |

分别报告计划数、已判定通过、已判定失败、未完成/未判定与返工。首次通过占比采用预先确定的全部计划首次尝试作为分母，同时列明未知项，不能只统计成功返回的请求。同一批任务里的多个子问题不是多个独立重复样本；批次计时不能拆成各任务耗时。

先检查是否达到原质量要求，再比较总耗时、返工和可信资源用量，不把它们压成一个随意加权的总分。较强模型调用比例不等于验收通过率；调节调用比例不能替代结果验证。

任务结果已核验但运行身份未验证时，结果按“请求组合”列示，模型归因标 PARTIAL，不宣称已验证某模型能力。身份不匹配、样本不足、验收不可靠或缺少所需计量时，保留原映射并说明未覆盖部分，不宣布性能/成本收益。小样本中未发现差异也不证明能力等价。

证据足够且有用户授权时，先复制为自定义档位，在独立样本中复核后再保存选择；不自动覆盖内置模式。模型、effort、工具、上下文或供应商变化后重新判断既有证据的适用性，不设无依据的固定有效期。

任务信号参考 [codex-auto-model-router](https://github.com/orange-the-weak/codex-auto-model-router/blob/main/references/routing-criteria.md)，数据校准思想参考 [RouteLLM](https://github.com/lm-sys/RouteLLM#threshold-calibration)。这里评估的是子代理任务的验收与执行组合，不直接套用其阈值、训练数据或研究中的收益数字。
