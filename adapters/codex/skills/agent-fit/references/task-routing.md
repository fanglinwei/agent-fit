# 同级任务候选

先按推理需求选择 L1–L4，并落实错误后果与可验证性的保障下限，再选择任务类型。任务类型不改变职责、独立性要求或允许动作；规模与处理深度只帮助在同级内选候选，不按文件数自动升复杂度。以下是本地待校准策略，不是已验证的模型能力排名。

## cut / official 的候选

| task | 可用等级 | 任务条件 | 主组合 |
| --- | --- | --- | --- |
| mechanical | L1 | 输入、方法和验收明确，机械执行 | Luna / medium |
| bounded | L2 | 有界的局部分析，产出容易核验 | Luna / high |
| scan | L1/L2 | 范围和检查方法明确，需要较广覆盖的扫描或审查 | Luna / xhigh |
| deep | L1/L2 | 确定性方法下需要较深处理和多步核对 | Luna / max |
| complex | L2/L3 | 有界复杂问题，需要局部或多约束权衡 | Sol / medium |
| uncertain | L3/L4 | 高歧义、强耦合，或高后果且难以验收 | Astra / low |
| reasoning | L3/L4 | 复杂推理，或证据表明先前结果推理不足 | Astra / medium |
| latency | 任意等级，仅显式配置 | 用户明确时延要求，且该组合满足原质量与能力要求 | 读取自定义候选，不内置 Terra |

L1/L2 的 scan、deep 只适用于边界明确的工作；出现强耦合、不确定假设或高后果且难验收时，先升至适当等级，再选 complex、uncertain 或 reasoning。不能为了保留 Luna 候选降低保障等级。审查本身不自动选择 scan；独立审查仍须独立执行。

普通自动 Astra 路由从 low 开始，复杂推理或有证据的质量升级最多 medium；备用也不能自动引入更高 Astra 强度。只说“Astra”不授权 high/xhigh/max/ultra。用户明确指定完整组合时优先；若当前档位没有该候选，先报告并在获授权的配置中保存，不临时拼模型与 effort。

## 最高强度与自定义授权

用户明确选择 high 或 fire，即授权其展示的最高强度组合，包括 Astra/ultra；它们保持原四级主组合，不被普通任务候选降为 low/medium。仅预览、explain、创建或保存定义不构成选择。已选择的自定义档位按保存的基线和候选执行，包括显式保存的高强度组合；复制后尚未选择时同样不构成派发授权。原预算、任务权限、宿主支持及 fire 会话验证仍须满足。

低延迟是质量约束内的偏好，不能只凭名称或 effort 声称更快。Terra 保留为旧版可显式配置路线，需要真实模型 ID 与宿主支持证据；不自动检测或尝试。未配置 latency 时，查询返回 TASK_ROUTE_NOT_CONFIGURED；不能静默改用其他模型并声称满足时延。仍可由主会话完成或报告受影响部分。

## 查询、快照与编辑

查询使用 `explain --level <等级> --task <类型> --role <原职责>`，同时传入 Skill 要求的 home、scope、project 和线程上下文。核对返回的 task、primary、fallback、来源及完整 task_profile。未给 --task 时保留等级基线，供旧定义、自定义无候选或明确使用基线的场景；它不自动识别任务。明确请求的候选缺失时阻断该路由，不能拿包内新值替代已安装任务快照。

每级可选 tasks 对象；每项完整保存 model、effort、fallback（可为 null）。候选备用遵守同级备用条件，不借用基线备用。CLI 单级修改只改基线与其备用，保留任务候选；整表 JSON 或网页每级的“任务候选 JSON”可修改候选，{} 清空。复制档位及三层作用域均保留候选。模型手动检测覆盖基线与候选的去重主组合，不检测备用；配置和查询不发模型请求。

任务开始时冻结基线、全部候选及其备用。先前 low 结果有推理不足证据时，可在原 L3/L4 的快照中选 reasoning 的 Astra/medium，属于同级候选的质量升级；不能以此重置计数。已使用 medium 后，不自动转 high/xhigh/max/ultra。其他组合是否值得更换仍需原验收和能力依据，不能仅按不同名称推断升级。

次数、预算、故障分类、写入者停止及 PARTIAL/BLOCKED 返回继续遵守 [失败处理](failure-policy.md)。规则一致性、配置查询与真实任务能力分开评估，参见 [校准指南](calibration.md)。
