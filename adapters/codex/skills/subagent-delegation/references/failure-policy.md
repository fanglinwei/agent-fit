# Failure policy

根据宿主可信的结构化 code、type 和请求阶段分类。HTTP 状态或自然语言报错不足以确定原因；无法分类时保留 unknown，不自动升级或替换。

| 情况 | 处理 |
| --- | --- |
| 认证失效、账号或工作区权限不足 | 停止该路径，提示用户处理账号；不读凭据、不更换供应商，不把目录存在当作权限 |
| 额度、账单或预算限制 | 停止新增请求，不触发备用；不能把更便宜模型当作绕过额度的方法 |
| 临时限流、服务故障 | 在原预算内按宿主 Retry-After 有限重试，不提前重试；cut、official、high 重试后仍失败时，在剩余次数与等待预算内自动尝试本级唯一备用；累计重试等待将超过 30 秒则停止 |
| 模型或 effort 不支持、输入/工具/上下文能力不符 | 使用明确且满足原能力与验收的备用；没有候选或授权则 BLOCKED，不静默删减输入或验收 |
| 资料缺失、工具故障、目标冲突、验收不明确 | 先补前提，仅阻断受影响部分；换强模型不解决这些原因 |
| 结果错误且证据充分 | 定位困难部分，复核推理；在用户选择和预算允许时提高该部分等级，不重复全部任务 |
| 超时、取消、停止状态未知 | 区分请求前失败与已启动工作。写入职责先确认旧 worker 停止并核对部分产出；未知时不得创建第二个同范围写入者 |

备用必须同时满足 current-mode.json 中的固定条件码：用户选择、原预算、宿主模型与 effort 支持、原任务输入及工具能力、原职责与验收、原写入 worker 已停止。条件码是待核对前提，不授予新的委派权限。cut、official、high 的档位选择默认允许原已授权任务自动使用本级唯一备用，无需逐次确认；用户明确锁定模型或禁止降级时不切换。备用耗尽后停止该委派并报告原因、实际组合与部分产出，不尝试其他模型或切换档位。备用使用 task_delegate 显式指定 model/effort，保留原职责；L3、L4 不自动降到 Luna。

每任务最多三次主代理发起的委派，包含主组合重试与备用接续，同一组合最多额外一次；累计重试等待不超过 30 秒并遵守 Retry-After。宿主已重试或次数未知时不叠加重试；不自动撤销他人修改，异常/部分结果仅作 PARTIAL 证据返回。经济模式的复杂任务不能自动降到 Luna；fire 检查失败、未完成或最高组合不可用时，使用用户指定组合，否则继承父代理实际模型与推理强度；通过 task_delegate 保留原职责，不自动切换 high。继承仍须核对原预算、能力、权限与写入者停止状态，无法确认父代理组合时阻断该委派。
